## 4. Contradictions found in the report or other notes

1. EA patent US7403202 (report, "The behaviour layer"; pass-one Q4 and Q5). The report says the patent "halves per-part force and torque limits during collisions and minimises them on ground contact". The patent ties joint strength to the active supervisor state: about half of running strength while falling, "a small percentage" while staying down, "nearly all" on standby while getting up (Section 1b). The design consequence differs: strength should be scheduled per behaviour state (fall / stay-down / get-up), which is what Overgrowth's per-type `ragdoll_strength` and Euphoria's per-behaviour stiffness also do, rather than gated on contact events. The "support polygon" wording should become "support circle from shin/foot COM positions, with pelvis+torso COM average and an animation-agreement sanity check".
2. Jolt spring frequency vs tick rate (report, "Tick rate: 120 Hz with interpolation"). The report derives "Jolt's 'stiff' 20 Hz drive therefore needs ≥ 80 Hz" from Catto's four-steps-per-period rule. Two problems: Catto states that rule for semi-implicit Euler force springs and, in the same slides, shows that soft constraints are implicit-Euler springs that are "always stable"; Jolt's motors are soft constraints, and Jolt's own bound is 0.5 × simulation frequency, with 20 Hz described as "a good value for a stiff spring" at 60 Hz (Section 1e). The pass-one Godot/Jolt note states the same 0.5 × rule ("a 60 Hz tick caps drive frequencies at 30 Hz"). So the 80 Hz figure is unsupported; 120 Hz can still be argued from script-side explicit forces and contact quality, and it raises the frequency cap to 60 Hz, but not from a 20 Hz motor "needing" it.
3. BodyBalance bracing (report, "The behaviour layer"). "BodyBalance ... braces with BraceStiffness 12" omits that BodyBalance's `BraceDistance` default is −1, which disables bracing until set ≥ 0 (pass one recorded this; the report dropped it).
4. Overgrowth fall-strength formula (pass-one Q2 and Q5, report). `clamp(0.1·|v|, 0, 0.8) − ragdoll_limp_stun` is written in a way that can go negative; the code clamps after subtracting the stun. Harmless for the report's use, but the copyable rule is `max(0, min(0.8, 0.1·|v|) − stun)`.
5. GDC Vault ID for the Uncharted 4 talk (pass-one Q4). Pass one cites 1024594; the Vault page found this pass is 1024087 with the same title and overview. Both should be listed until one is confirmed dead.
6. US7685081 original assignee (pass-one Q1). Pass one says "Isis Innovation/Oxford"; Google Patents displays "Oxford University Innovation Ltd". Not a factual conflict if the rename is accepted, but the note should quote what the record shows.
7. Attribution error in a search summary, caught before it entered the notes: the itch.io "PID similarities but simulates muscles" post is No Brakes Games (Human: Fall Flat), not Boneloaf (Gang Beasts). Any future note that credits Boneloaf with that quote is wrong.
8. Pass-one Q6 and the report's camera section rely on the Boneworks fan-wiki description of three colliders (waist, torso, head); Laatsch's own count is six rigidbodies for Boneworks and 11 for Bonelab, 18 for Marrow 2 (Section 2c). Not contradictory (the wiki names only the collision skeleton) but the primary figure should replace the wiki's.
9. No contradiction was found between the report and the biped-control note on SIMBICON gains, Stable PD, Catto or Zordan; the report's "Torque magnitudes are limited to kp" (3D SIMBICON) and the 0.3 s dwell are confirmed by the paper and by the biped note's Table 1 transcription.
